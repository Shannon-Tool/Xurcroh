# 09. Memory Security

<Evidence type="limitation">Cleanup mechanisms do not imply universal physical erasure</Evidence>

The CPU lifecycle tracks request ownership. `KVCachePool` wipes physical slots before reuse and rejects cross-user frees. `RequestMemory` wipes tensors and mutable buffers. `ClientBoundary` zeroes its embedding/head store on close. Python memory telemetry contains counts, never request content.

## Native controls

`xurcroh_burn_alloc.cu` zeros on allocation and on free. The free path issues `cudaMemsetAsync` and synchronizes the allocation stream before `cudaFree`, preventing reuse through that allocator before the wipe completes. KV pools need separate wipes because logical release never reaches the allocator.

ChaCha20 kernels implement actual 20-round block generation and modulo-\(2^{16}\) mask/unmask. The shared-memory epilogue and uniform page-touch path are best-effort mitigations. They cannot prove all physical registers, every SRAM location, or another device’s local memory is clear.
